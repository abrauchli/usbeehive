# Quick Task 260905-tb1 — Trimmed FURTHER-WINS subset: `port.*`, `hub.*`, `power.source`, `kernel.quirks`, `product_db`

## Goal

A read-only survey (`.planning/specs/FURTHER-WINS.md`) found ~30 unexploited
sysfs primitives and specified an additive D-Bus contract for all of them
(`.planning/specs/DBUS-FURTHER-SPEC.md`). The user reviewed that contract and
chose a **deliberately trimmed subset**. Implement exactly that subset,
purely additively, keeping the interface at `org.usbeehive.Devices5`.

## In scope — exactly 11 keys

From DBUS-FURTHER-SPEC §A (physical connector / port):
`port.id`, `port.peer_id`, `port.peer_state`, `port.connect_type`,
`hub.ports_total`, `hub.ports_used`

From §B (power source / budget):
`power.source`, `hub.power_budget_ma`, `hub.power_committed_ma`

From §D (kernel quirks):
`kernel.quirks` — rendered from the **already-read** `UsbDevice.quirks`
bitmask landed by 260905-ta1. No second sysfs read.

From §G:
`product_db` — hwdb model-name lookup through the existing `udev` crate.

## Explicitly deferred (do NOT implement)

All of §C (`pm.*`, `connected_s`), all of §E (`function.*`), all of §F
(`interface.N.name`, `usb.configurations`), the `PortOverCurrent` signal
(§H), and `hub.multi_tt`, `power.remote_wakeup_capable`,
`kernel.avoid_reset`, `authorized`.

## Locked decisions

1. **Interface stays `Devices5`.** Everything rides the per-entry
   `properties` `a(ss)` bag (position 14), documented non-breaking. No tuple
   shape, method signature, enum, or field position changes. No new signal.
2. **Dotted key names kept verbatim from the spec** (`port.*`, `hub.*`,
   `power.source`, `kernel.quirks`) — consistent with the existing dotted
   namespaces `transport.*`, `cable.no_emarker`, `cable.trust.*`.
3. **Fingerprint discipline.** `port.peer_state` joins `state_fingerprint()`
   (a companion port training late is exactly the transition consumers want),
   together with the static `power.source` and `kernel.quirks`. The
   occupancy/budget keys (`hub.ports_used`, `hub.power_committed_ma`) stay
   **out** — they move only on plug/unplug, which already fires
   `DeviceAdded` / `DeviceRemoved`. Nothing added may make `DeviceChanged`
   chatter on an idle machine.
4. **Absence is information.** Every key is optional; a missing key means
   "unknown / not applicable", never zero.
5. **`port.connect_type == "unknown"` is omitted** rather than emitted. The
   kernel writes the literal string `unknown` on every hub-internal port
   (verified live: all of `5-2-port1..4`, `5-2.1-port1..4`,
   `5-2.4-port1..3`); emitting it would put a useless key on the majority of
   entries and contradicts the spec's own "absence means unknown" convention.
6. **`product_db` is gated on the `watch` feature** (that is where the `udev`
   dependency lives). Builds without it simply omit the key.
7. No version bump, no tag, no push. `../usbee` untouched.

## Tasks

1. **Model + derivations** (`src/usb.rs`) — additive `UsbDevice` fields
   (`port_id`, `port_peer_id`, `port_peer_state`, `port_connect_type`,
   `max_child`, `ports_used: Option<u32>`, `bm_attributes`, `product_db`),
   all `#[serde(default)]`; plus `quirk_names()` (bits 0–18 of the running
   kernel's `include/linux/usb/quirks.h`), `self_powered()`,
   `hub_power_budget_ma()`, `hub_power_committed_ma()`. Unit tests.
2. **sysfs reads** (`src/sysfs/usb.rs`) — resolve the `port` symlink, its
   `connect_type`, its `peer` symlink and the peer's `state`; count occupied
   downstream ports for hubs; read `bmAttributes`; hwdb `product_db` behind
   `cfg(feature = "watch")`. Fixture-builder helpers + integration tests.
3. **Wire surface** (`src/summary.rs`, `src/sysfs/manager.rs`,
   `src/output.rs`, `src/dbus.rs` docs) — emit the 11 keys, extend
   `state_fingerprint()` per decision 3, add CLI display labels, document the
   keys in the `dbus.rs` wire-surface table. Tests incl. an idle-stability
   test proving `DeviceChanged` does not chatter.
4. **Docs** — move both scratchpad specs into `.planning/specs/`, annotate
   `DBUS-FURTHER-SPEC.md` with IMPLEMENTED / DEFERRED status, write
   `.planning/specs/DBUS-TRIM-CONSUMER-SPEC.md`, add a CHANGELOG entry.
