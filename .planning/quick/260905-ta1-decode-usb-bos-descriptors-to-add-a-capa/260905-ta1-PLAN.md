# Quick Task 260905-ta1 — Decode USB BOS descriptors → capability-vs-negotiated data-rate signal

## Goal

The crate currently reads only what a USB link **negotiated** (`speed`,
`rx_lanes`, `tx_lanes`). `/sys/bus/usb/devices/*/bos_descriptors` exposes what
the device is **capable** of. Decode it and surface a conservative
capability-vs-negotiated comparison — purely additively, keeping the D-Bus
interface at `org.usbeehive.Devices5`.

## Locked decisions

1. **Interface stays `Devices5`.** New data rides in the per-entry
   `properties` `a(ss)` bag (explicitly documented non-breaking) plus two new
   signals (`DeviceChanged` in 0.10.x is the precedent). The `DeviceEntry`
   tuple shape is NOT touched — that would force a Devices6 hard cut.
2. **Data-rate ≠ charging.** `Bottleneck` / `ChargingDiagnostic` /
   `CapabilityDegraded(iss)` are power-side and keyed on Type-C **port
   numbers**. A plain USB hub device has no port number. So a new,
   separately-named concept `DataRateAssessment` / `DataRateVerdict` keyed on
   the string summary `id` is introduced, with its own
   `DataRateDegraded(sss)` / `DataRateRestored(s)` signals. Nothing is jammed
   into the charging types.
3. **Absence is normal.** `bos_descriptors` is absent on USB-2.0-only devices.
   `Option`, never an error. `src/sysfs/error.rs` is untouched — its own doc
   comment states missing files yield empty/`None` results and `Error` is
   reserved for misconfiguration.
4. **`bFunctionalitySupport` suppresses false positives.** A device is only
   flagged `Degraded` (`is_warning == true`) when the negotiated speed is
   below the **vendor's own declared functionality floor**. A device that
   declares full functionality at High Speed and is linked at High Speed is
   `BelowCapability` (informational) even though it also advertises
   SuperSpeed. No floor declared ⇒ never a warning.

## Tasks

### T1 — `src/bos.rs` pure parser + assessment
- No IO, no feature gate (sits with `pd.rs` / `usb.rs` in the always-on layer).
- `parse(&[u8]) -> Option<BosDescriptors>`; robust against truncation,
  `bLength == 0` (must not loop), `wTotalLength` past end-of-blob, unknown
  capability types (preserved as `Other { cap_type, data }`).
- Capabilities: `0x02` USB 2.0 Extension, `0x03` SuperSpeed, `0x04`
  Container ID, `0x0A` SuperSpeedPlus (full sublink speed attribute array —
  mantissa/exponent/type/protocol + min lane counts, so Gen1x2 and Gen2x1
  are distinguishable), everything else `Other`.
- `max_capable_mbps()`, `functional_floor_mbps()`, `gen_label()`.
- `DataRateAssessment::evaluate(negotiated_mbps, &BosDescriptors)`.
- Unit tests against the four real blobs captured from this machine plus
  synthetic truncated / zero-`bLength` / empty / junk inputs.
- **Verify:** `cargo test --no-default-features bos`

### T2 — sysfs read + `UsbDevice.bos`
- `reader::read_bytes(path) -> Option<Vec<u8>>` (size-capped, `None` on
  missing/unreadable/empty).
- `UsbDevice.bos: Option<BosDescriptors>` populated in
  `src/sysfs/usb.rs::from_sysfs`.
- **Verify:** `cargo test` + live check against `5-2.1.1`, `5-2`, `usb2`.

### T3 — surface: summary properties, typed field, diff, D-Bus signals, CLI labels
- `DeviceSummary.data_rate: Option<DataRateAssessment>` (`#[serde(default)]`,
  same additive pattern as `TypeCPartner.usb_name`).
- New `properties` keys (all optional, omitted when unknown):
  `usb_capable_speed_mbps`, `usb_capable_speed`, `usb_capable_gen`,
  `usb_capable_rx_lanes`, `usb_capable_tx_lanes`,
  `usb_functional_floor_mbps`, `usb_link_verdict`, `usb_link_degraded`,
  `usb_bos_container_id`.
- `SnapshotDiff.newly_rate_degraded: Vec<String>` /
  `rate_restored: Vec<String>` (string ids).
- `usb_link_verdict` joins the curated `state_fingerprint` so a verdict flip
  also wakes `DeviceChanged` consumers.
- `DevicesIface::data_rate_degraded(id, summary, detail)` and
  `data_rate_restored(id)` zbus signals; emitted from
  `src/bin/usbeehived.rs::emit_signals`.
- `src/output.rs` display labels for the new keys.
- **Verify:** `rtk proxy cargo test --all-features`

### T4 — docs + consumer spec
- `.planning/specs/DBUS-BOS-CONSUMER-SPEC.md` (client-author-facing, with
  worked values from the real devices on this box + proposed English display
  labels for `usbee`'s `label-table.js`).
- `src/dbus.rs` module docs (properties row + signal table).
- CHANGELOG `## [Unreleased]`, AGENTS.md key-files row.
- **Verify:** `rtk proxy cargo fmt --all --check`,
  `rtk proxy cargo clippy --all-targets --all-features -- -D warnings`.

## Out of scope
- No crate version bump, no tag, no push (orchestrator owns releases).
- No changes to `../usbee`.
- `bos_descriptors` continues to leak into `UsbDevice.raw_attributes` for
  blobs that happen to be valid UTF-8 (pre-existing `read_all_attrs`
  behaviour); not changed here to avoid altering `--raw` output.
